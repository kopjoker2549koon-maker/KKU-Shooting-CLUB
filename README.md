## 1. ข้อมูลภาพรวมโครงการ (Project Overview)

ระบบบริหารจัดการชมรมกีฬายิงปืน มหาวิทยาลัยขอนแก่น พัฒนาขึ้นเพื่อยกระดับการดำเนินงานของชมรมสู่ระบบดิจิทัลที่ได้มาตรฐาน ครอบคลุมตั้งแต่กระบวนการรับสมัครสมาชิก การยืนยันตัวตนด้วยบัญชีอีเมลสถาบัน การออกบัตรสมาชิกดิจิทัลพร้อมรหัสคิวอาร์ (QR Code) ประจำตัว การสั่งจองกระสุนและเป้าซ้อมยิง การตรวจสอบสลิปการโอนเงิน ตลอดจนการตัดเบิกจ่ายอุปกรณ์ ณ ช่องยิงด้วยระบบสแกนเนอร์แบบเรียลไทม์ พร้อมระบบรายงานสถิติและเครื่องมือการบริหารงานสำหรับคณะกรรมการและที่ปรึกษาชมรม

## 2. บทบาทและสิทธิ์การเข้าถึงระบบ (User Roles & Access Control)

ระบบแบ่งระดับผู้ใช้งานออกเป็น 3 บทบาทหลัก ตามโครงสร้างการบริหารงานของชมรม:

| บทบาท (Role) | สิทธิ์การเข้าถึง (Access Level) | หน้าที่และความรับผิดชอบหลัก |
| :--- | :--- | :--- |
| **สมาชิกชมรม (Member)** | `/member`, `/member/card` | สมัครสมาชิก, ดูบัตรสมาชิกดิจิทัลพร้อม QR Code, ตรวจสอบยอดกระสุนและเป้าซ้อมในกระเป๋าส่วนตัว, สั่งซื้อกระสุนและเป้าซ้อม, แนบหลักฐานการชำระเงิน, ติดตามสถานะคำสั่งซื้อ |
| **คณะกรรมการชมรม (Committee / Operator)** | `/operator` | ตรวจสอบและอนุมัติสลิปการโอนเงินของสมาชิก, สแกน QR Code บัตรสมาชิก ณ สนามยิงปืนเพื่อตัดเบิกจ่ายกระสุนลงช่องยิง, จัดการยอดคงเหลือในคลังพัสดุชมรม, บันทึกประวัติการเบิกจ่าย |
| **ผู้ดูแลระบบสูงสุด (God Admin / Executive)** | `/god` | กำกับดูแลระบบทั้งหมด, ตรวจสอบและอนุมัติคำขอเปิดบัญชีกรรมการชมรม, จัดการสิทธิ์และรีเซ็ตรหัสผ่าน, ตรวจสอบรายงานธุรกรรมและการเงิน, ส่งออกรายชื่อสมาชิก (Excel / CSV), สำรองฐานข้อมูลระบบ |

## 4. ฟังก์ชันการทำงานหลัก (Core System Features)

### 4.1 บัตรสมาชิกดิจิทัลและระบบสแกนเนอร์สนาม (Digital Membership Card & Range Scanner)
- บัตรสมาชิกดิจิทัลดีไซน์ Obsidian Blue และ Amber Accent รองรับการแสดงผลทุกขนาดหน้าจอ
- ฝัง Dynamic QR Code ประจำตัวสมาชิก เข้ารหัสข้อมูลหมายเลขสมาชิก รูปถ่าย และข้อมูลสังกัดคณะ
- สแกนเนอร์หน้าสนาม (Range Scanner) พัฒนาด้วย Local Library (`html5-qrcode.min.js`) ทำงานผ่านกล้องอุปกรณ์มือถือหรือแท็บเล็ตได้ทันทีโดยไม่ต้องเชื่อมต่ออินเทอร์เน็ตภายนอก
- รองรับการค้นหาสมาชิกด้วยการพิมพ์ชื่อ นามสกุล หรือรหัสนักศึกษา เป็นช่องทางสำรองเมื่อไม่สะดวกใช้กล้อง

### 4.2 ระบบคลังพัสดุและมาตรการป้องกันการเบิกจ่ายเกินยอด (Inventory Guardrails)
- จัดการประเภทกระสุนและเป้าซ้อมมาตรฐาน:
  - กระสุนขนาด .177 นิ้ว (ลูกเบอร์ 1 สำหรับปืนสั้นและปืนยาวอัดลม)
  - กระสุนขนาด .22 LR (ยี่ห้อ CCI Standard Velocity)
  - กระสุนขนาด .22 LR (ยี่ห้อ RWS Target Rifle)
  - เป้าปืนสั้นมาตรฐาน และ เป้าปืนยาวมาตรฐาน
- ระบบตรวจสอบเงื่อนไขความถูกต้อง (Safety Validation): ป้องกันไม่ให้สั่งลดจำนวนอุปกรณ์เกินกว่ายอดคงเหลือที่มีอยู่จริงในคลัง โดยระบบจะปฏิเสธคำสั่งและแจ้งเตือนข้อผิดพลาดทันที

### 4.3 ระบบตรวจสอบและอนุมัติการสั่งซื้อ (Order & Slip Verification)
- สมาชิกสามารถเลือกซื้อกระสุนและเป้าซ้อมตามโควตาที่กำหนด พร้อมระบบคำนวณราคาสุทธิอัตโนมัติ
- แสดง QR Code สำหรับชำระเงินผ่านระบบ PromptPay ของชมรม
- ระบบครอปตัดภาพสลิปธนาคารแบบโต้ตอบ (Interactive Image Cropper) ช่วยให้สมาชิกจัดวางภาพสลิปได้คมชัดก่อนส่งเข้าระบบ
- คณะกรรมการสามารถตรวจสอบภาพสลิป ยอดเงิน วันที่และเวลาโอนเงิน ก่อนกดอนุมัติหรือปฏิเสธพร้อมระบุเหตุผล เมื่ออนุมัติแล้วยอดอุปกรณ์จะเข้าสู่กระเป๋าของสมาชิกทันที

### 4.4 ความปลอดภัยของข้อมูลและการยืนยันตัวตน (Security & Cryptography)
- จัดเก็บรหัสผ่านด้วยการเข้ารหัสแฮชทางเดียวมาตรฐาน **Scrypt** (ผ่าน Werkzeug Security) ป้องกันการโจมตีแบบ Brute-force และ Rainbow Table
- จำกัดการลงทะเบียนเฉพาะนักศึกษาและบุคลากรที่มีบัญชีอีเมลโดเมน **`@kkumail.com`** เท่านั้น
- ระบบกู้คืนรหัสผ่านด้วยรหัสผ่านใช้ครั้งเดียว (One-Time Password: OTP) ส่งตรงไปยังอีเมลสถาบัน โดยรหัสมีอายุการใช้งานจำกัด 5 นาที
- จัดการเซสชันอย่างปลอดภัยด้วย `HttpOnly`, `SameSite=Lax` และคีย์ลับแบบถาวร (Persistent 256-bit Secret Key)
- รองรับข้อตกลงและกฎความปลอดภัย 4 ประการแห่งการใช้อาวุธปืน (Four Universal Gun Safety Rules) ก่อนยืนยันการสมัครสมาชิก

### 4.5 ระบบการจัดเก็บรูปโปรไฟล์และรูปภาพมาตรฐาน (Avatar Management)
- สมาชิกและกรรมการสามารถอัปโหลดและครอบตัดรูปโปรไฟล์สัดส่วน 1:1 ได้อย่างอิสระ
- สำหรับผู้ใช้งานที่ไม่ได้อัปโหลดรูปภาพ ระบบจะกำหนดรูปภาพมาตรฐาน (Default Gray Avatar) เป็นรูปเงาศีรษะและลำตัวโทนสีเทาสากลอย่างเป็นระเบียบ

### 4.6 ระบบส่งออกข้อมูลและรายงาน (Reporting & Data Export)
- ส่งออกรายชื่อสมาชิกชมรม ข้อมูลคณะ ชั้นปี หมายเลขโทรศัพท์ และยอดกระสุนคงเหลือ เป็นไฟล์ **CSV และ Excel**
- ไฟล์ส่งออกรองรับการเข้ารหัส **UTF-8 พร้อม Byte Order Mark (BOM)** สามารถเปิดด้วย Microsoft Excel ภาษาไทยได้ทันทีโดยสระและพยัญชนะไม่ผิดเพี้ยน สำหรับนำส่งกองพัฒนานักศึกษาและศิษย์เก่า (กพศ. มข.)

## 5. สถาปัตยกรรมและเทคโนโลยีที่ใช้ (Architecture & Technology Stack)

| ส่วนประกอบ (Component) | เทคโนโลยีที่เลือกใช้ (Technology) | รายละเอียดทางเทคนิค (Technical Details) |
| :--- | :--- | :--- |
| **ภาษาหลักและเฟรมเวิร์ก** | Python 3.14 / Flask 3.1 | Core Backend Application & REST API |

| **การสนับสนุน PWA** | Service Worker Cache v2, Web Manifest | รองรับการติดตั้งแบบ Web App บนหน้าจอมือถือ (iOS / Android) |

    ├── member.html             # แดชบอร์ดและร้านค้าอุปกรณ์สำหรับสมาชิก

## 7. ข้อกำหนดระบบและการติดตั้ง (System Requirements & Setup)

### 7.1 ข้อกำหนดขั้นต่ำของระบบ
- **ระบบปฏิบัติการ:** Microsoft Windows 10 / 11, Windows Server หรือ Linux Ubuntu 20.04 ขึ้นไป
- **สภาพแวดล้อมภาษา:** Python 3.10 ขึ้นไป (แนะนำ Python 3.12 - 3.14)
- **หน่วยความจำ (RAM):** ขั้นต่ำ 2 GB (แนะนำ 4 GB ขึ้นไป)
- **พื้นที่จัดเก็บข้อมูล:** ขั้นต่ำ 500 MB สำหรับระบบและฐานข้อมูล

### 7.2 ขั้นตอนการติดตั้งไลบรารี
เปิดหน้าต่าง Terminal หรือ PowerShell ในโฟลเดอร์โปรเจกต์ แล้วเรียกใช้คำสั่ง:

```powershell
py -m pip install --upgrade pip
py -m pip install -r requirements.txt
```

## 8. การเปิดใช้งานระบบในสภาพแวดล้อมจริง (Production Deployment)

### 8.1 การเปิดใช้งานบนระบบปฏิบัติการ Windows (แนะนำ)
ดับเบิลคลิกที่ไฟล์ **`start_server.bat`** ในโฟลเดอร์โปรเจกต์ ระบบจะดำเนินการตรวจสอบสภาพแวดล้อมและเริ่มต้นการทำงานผ่าน Waitress WSGI Server โดยอัตโนมัติ

### 8.2 การเปิดใช้งานผ่านคำสั่ง Command Line / PowerShell
```powershell
py run.py
```

### 8.3 ที่อยู่สำหรับเข้าใช้งาน (Access URLs)
- **เครื่องเซิร์ฟเวอร์ (Localhost):**
  `http://localhost:5000`

  `http://[หมายเลข_IP_ของเครื่องแม่ข่าย]:5000` (เช่น `http://10.10.1.32:5000`)

## 9. การสำรองและกู้คืนฐานข้อมูล (Database Backup & Disaster Recovery)

### 9.1 การสำรองฐานข้อมูลออนไลน์ (Online Hot Backup)
1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบสูงสุด (`/god`)
2. ในแถบเมนูเครื่องมือระบบ คลิกปุ่ม **"สำรองฐานข้อมูล (.db)"**
3. ระบบจะเรียกใช้ฟังก์ชัน `sqlite3.backup()` เพื่อสร้างสำเนาข้อมูลแบบ Atomic Snapshot บันทึกลงในไดเรกทอรี `backups/` โดยไม่รบกวนการทำงานของผู้ใช้ที่กำลังใช้งานอยู่

### 9.2 ขั้นตอนการกู้คืนข้อมูล (Disaster Recovery Procedure)
1. หยุดการทำงานของเซิร์ฟเวอร์โดยกด `Ctrl + C` ในหน้าต่างคอนโซล
2. ไปที่ไดเรกทอรี `backups/` และเลือกไฟล์สำรองที่ต้องการกู้คืน (เช่น `backup_shooting_club_20261030_104500.db`)
3. ทำการคัดลอกและเปลี่ยนชื่อไฟล์ดังกล่าวเป็น `shooting_club.db` เพื่อนำมาแทนที่ไฟล์เดิมในโฟลเดอร์หลัก
4. ลบไฟล์ชั่วคราว `shooting_club.db-wal` และ `shooting_club.db-shm` (หากมี)
5. เริ่มต้นเซิร์ฟเวอร์ใหม่ด้วยคำสั่ง `py run.py`

## 10. มาตรการความปลอดภัยและข้อกำหนดการใช้งาน (Security & Safety Compliance)

1. **การคุ้มครองข้อมูลส่วนบุคคล (PDPA Compliance):**
   - รหัสผ่านของผู้ใช้งานทุกคนจะถูกเข้ารหัสแฮชด้วย Scrypt ทันทีที่ลงทะเบียน โดยไม่มีการจัดเก็บรหัสผ่านในรูปแบบข้อความธรรมดา (Plaintext) ในระบบ
   - การจัดเก็บข้อมูลนักศึกษาจำกัดเฉพาะข้อมูลที่จำเป็นต่อการยืนยันสิทธิ์ในการเข้าใช้สนามยิงปืนของมหาวิทยาลัยขอนแก่นเท่านั้น

2. **กฎความปลอดภัยสากลในการใช้อาวุธปืน (Four Universal Rules of Gun Safety):**
   - พึงระลึกเสมอว่าปืนทุกกระบอกมีกระสุนบรรจุอยู่ (Treat every gun as if it were loaded)
   - ห้ามชี้ปากกระบอกปืนไปทางสิ่งใดก็ตามที่ท่านไม่ต้องการทำลาย (Never point a firearm at anything you are not willing to destroy)
   - นิ้วต้องอยู่นอกโกร่งไกเสมอจนกว่าศูนย์ปืนจะทาบเป้าหมายและพร้อมที่จะยิง (Keep your finger off the trigger until your sights are on target and you have decided to fire)
   - มั่นใจในเป้าหมายและสิ่งที่อยู่ด้านหลังเป้าหมายเสมอ (Be sure of your target and what is beyond it)
   - ผู้สมัครสมาชิกและกรรมการทุกคนต้องยินยอมปฏิบัติตามกฎความปลอดภัยอย่างเคร่งครัดผ่านระบบก่อนได้รับการอนุมัติใช้งาน
